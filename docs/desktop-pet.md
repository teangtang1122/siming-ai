# 司命桌宠

## 当前唯一运行路径

Windows PyWebView 透明悬浮窗 → `/desktop-pet` → `DesktopPetApp` → `poses/PoseCanvas` → 连续整图网格。
当前素材版本为 `poses-outfits-20261012`，提供经典长袍和朱红常服两套衣装，共用同一运行路径，不加载 Cubism SDK、MOC 或旧 Live2D 动作。

- 素材契约：`frontend/src/features/desktopPet/poses/manifest.json`。
- 运行素材：`frontend/public/desktop-pet/poses/`。经典长袍的 15 张纹理、6,439,267 字节及全部哈希不变；朱红常服新增 13 张 1024×1536 原始 RGBA PNG、22,263,384 字节；合计 28 张、28,702,651 字节。只加载当前衣装的纹理，不同时将两套上传到 GPU。所有姿势都使用同一个 384×576 逻辑画布；PNG 原始像素不改写，仅通过各姿势的等比对齐矩形登记到相同脚底和头部比例。
- 单一渲染器：`frontend/src/features/desktopPet/poses/renderer.ts`。
- 业务状态来自共享 operations API/SSE；桌宠不创建任务、不保存草稿、不建档、不自动续写。
- 网页、Gateway 和 Android 不创建 Windows 悬浮窗。共有任务状态继续遵循同一 operations 契约。

## Windows 透明背景

桌宠窗口明确使用 `DWMSBT_NONE`，不绘制 Mica 系统背景。PyWebView 6.2.1 在 Windows 应用深色模式下会为窗口设置 `DWMSBT_MAINWINDOW`；透明 WebView 仍会露出这一整块系统底色，导致 `#202020` 黑底。当前原生输入桥只为桌宠实例包装 `update_title_bar_theme`：保留依赖库的主题处理，随后重新禁止系统背景，并在 HWND 重建和重新显示时应用同一策略；关闭时恢复原方法。主窗口、操作系统主题和 WebView2 版本均不更改。Windows 10 及 Windows 11 22621 之前不支持该背景属性，不调用它；支持平台的 API 失败会明确报告。

原生合成测试在自有纯色底板上采样，既拒绝深灰 / 黑块，也核对透明区域实际透出底板颜色；负向对照主动为隔离预览启用 Mica，必须被检查拦截。深浅主题测试仅替换预览实例的主题查询结果，再调用依赖库真实的主题回调，不修改 Windows 设置；同时核对主窗口背景属性保持原值。

## 姿势和交互

右键菜单“衣装”可在“经典长袍”与“朱红常服”间切换并保存；主设置页的衣装选择仍须点击“保存桌宠设置”。默认保留经典长袍，已有设置无需迁移。唯一设置字段为 `desktop_pet_outfit: classic | casual`，API 和原生广播使用同一契约；无效枚举明确失败，不默默换回另一套。切换中取消过时加载并释放旧 GPU 资源，迟到结果不能盖回当前衣装；保存失败按既有草稿机制回退并提示。普通读书 / 睡眠 / 真实任务不因换装改变；若正处于紧凑探头则先恢复正常窗口，下一次探头按新衣装轮廓重新计算。

朱红常服由内置 image_gen 按当前五种动作绘制，包含短外套、收口袖、朱红褶裙及原有配饰。四个清醒姿势各有睁眼 / 半闭眼 / 闭眼三张，坐姿一张；新站姿通过 `frameMap` 把同一动作时钟的五个逻辑帧映射到三张眼睛图，不另起一套动作调度。新衣装四种眨眼全部仅替换两块眼区，边缘按素材配置羽化，身体、手、书和服装始终来自同一基准图。原衣装眼区和羽化参数保持不变。

| 真实状态 / 行为 | 姿势 |
| --- | --- |
| 待机、等作者、完成、错误 | 抱书站立 |
| 思考、写作；或空闲时右键选“翻翻小书” | 低头读书 |
| 空闲时打盹 | 坐着抱书睡觉 |
| 已确认停靠屏幕左 / 右边缘 | 贴边偷看，右侧镜像完整原画 |
| 指针位移超过拖动阈值，正在拖动 | 被轻轻拎起：抱紧书、双腿悬空、衣袖自然垂下 |

姿势直接切换，不做肢体补间。读书、探头、被拎起的眨眼仅采样两块旋转眼区；衣服、脸、手和书始终来自基准纹理。站姿保留已确认的五帧眨眼，坐姿保持闭眼。呼吸、点头和以脖子为中心的轻微歪头使用一张连续网格，脚底不漂移；没有拆开的手臂或袖子。头部主体保持刚性旋转，在领口向身体平滑衰减；点击、注视和自动动作共享颈部变形限额，不能叠加挤压领口。轻点时先约束当前自动动作与注视，再平滑插值到统一的回应姿态，不再把另一段点头直接相加后硬截断；回应峰值的 nod 为 6.7、headTilt 为 0.018，和自动动作之间的插值始终在同一颈部预算内。呼吸和眨眼不受打断，轻点回应持续约 850ms，结束时平滑接回仍在计时的自动小动作 / 注视。连续轻点从当前幅度接续，不突然归零、不叠加幅度或积压动作，最后一次轻点后 850ms 内结束。读书时偶尔抬头停留片刻，再回到书页。

鼠标跟随以当前姿势的脸部为中心，按实际画布位置和角色比例换算 CSS 坐标；不使用整个透明窗口的中心，也不把 DPI 像素当作 CSS 像素。气泡换边、置顶和左右紧凑探头均使用同一布局算法；右侧探头只镜像一次。只保留最新指针坐标，在绘制帧统一测量，不随高频鼠标事件反复读布局。姿势、大小或气泡方位改变时，静止指针也会重新换算；窗口缩小后已落在外部的旧指针、隐藏页面和睡眠 / 被拎起期间的注视不带到下一状态。轻按后松手仅清除拖动采样，保留注视和正在进行的点头；真正进入被拎起姿势才取消站姿回应，松手后不会重放之前的点头。

被拎起使用专门的完整悬垂画，不套用站姿的点头 / 呼吸变形，不持续摇袖子。水平拖动速度来自屏幕坐标，而非随原生窗口一起移动的局部坐标；整张姿势围绕头顶最多轻倾约 1.3°，没有独立甩动的袖子。鼠标停下后单调回正，不来回震荡；松手或取消拖动立即清除倾斜并恢复当前任务 / 环境姿势，不改变任务状态。轻点不触发被拎起姿势，拖动不弹气泡。

拖动位移统一由 `nativeDrag.ts` 调度：最多一个原生移动请求进行中，只保留最新待处理坐标，不排队重放旧帧；正常松手应用最终坐标后结束，重复坐标去重。快速再次拎起的视觉反馈即时生效，但原生 `begin` 必须等待上一手势的 `end` 回执，避免旧收尾关闭新拖动。返回失败或异常时结束已开启的会话，不误判为成功贴边。原生移动丢失 DOM 捕获后，活动手势仍在页面级接收同一指针的移动 / 松手；不把单纯的捕获丢失当作取消。取消、失焦、页面隐藏或卸载丢弃尚未发送的位移，等待已在途请求后收尾，不弹气泡、不触发探头，也不把取消事件中的零坐标当成新位置。迟到的上次放下位置不再改变新手势的气泡方位。

不使用固定八秒动作循环：眨眼间隔约 3.1～7.2 秒；站姿闭眼较快，睁开时先经过细缝、半睁再全睁，不从细缝直接跳回全睁。清醒姿势之间共享眨眼相位和下一次眨眼时间，切换读书 / 站立 / 被拎起不会截断眨眼或一直重置计时；睡醒后重新安排。首次小动作在切换姿势后约 3～5 秒出现，之后每次保留 10～18 秒安静间隔。待机随机选择点头 / 歪头，最大头部倾角约 2.3°；探头包含探出、停留观察、收回一点三个阶段。随机只用于安排小动作时间，不产生逐帧抖动。减少动态效果时仍完全静止；页面隐藏时清空点击 / 拖动的瞬态回应，回来不会重放旧反应。

气泡默认隐藏，轻点角色（键盘 Enter / 空格同效）才显示颜文字文案并点头回应，5 秒后用 180ms 淡出并从 DOM 和原生命中区域移除。再次轻点换一句并重新计算完整显示时间，淡出中点击也可恢复；悬停、拖动、切换姿势和任务状态变化都不会主动显示或延长气泡。任务和断线说明也采用同一点击展示规则。拖动保留原生边界限制，双击回书斋。右键菜单的“小动作”可立即体验读书、坐睡、左右探头；有真实任务或连接错误时禁用手动覆盖。新任务、点击和拖动结束休息姿势。睡眠可由鼠标唤醒；探头不因悬停而消失。

空闲十分钟后仍按 50% 打盹、25% 左探头、25% 右探头选择。拖到边缘放下也触发探头。原生窗口始终限制在当前显示器工作区，只有完整原画向侧边移出视口；不会单独隐藏身体，也不会在原生停靠失败时假装探头。

气泡显示时位于角色内侧，窄工作区可置顶。空闲、读书、打盹和探头的文案保留纸笺外观，正文为 12px；任务、断线或加载状态才显示标题，任务进度继续保留。操作提示移到右键菜单；探头使用短句气泡。各姿势共用头部比例和逻辑坐标，切换及气泡显隐不会自动放大。默认窗体 272×240（340×300 × 0.8），仍可调整大小、透明度、置顶、静音。菜单内容过多时内部滚动，不越出窗口。右键打开菜单，再次右键角色或菜单内任意位置即可收起；Esc 或左键点击桌宠窗口内的菜单外区域也可关闭。菜单内左键操作不关闭菜单；右键收起不触发说话、拖动或再次恢复窗口。

贴边探头时按露出的头发轮廓和气泡范围收窄原生窗口，鼠标输入层同步收窄；角色和气泡维持进入探头前的大小，气泡靠近脑袋并朝向屏幕内部。实际窗口尺寸随缩放设置、显示器 DPI 和气泡可见状态计算。唤醒、拖动或修改大小时先恢复完整窗口；重复探头不会累积缩小。原生层按 CSS 视口与窗口的比例换算尺寸，保持左 / 右工作区边缘锚定。

退出探头时，真实任务状态立即更新，但画布仍在紧凑尺寸期间保留对应侧的探头画面和点击轮廓；实际宽高恢复后才绘制任务 / 被拎起等完整姿势，不临时缩小角色，也不套用探头比例裁切完整姿势。原生恢复回执与画布尺寸确认共同结束本次布局，回执先到或后到均可；旧回执 / 旧画布确认不能清除新一次探头。恢复期间再次停靠仍使用进入前的完整尺寸，调整大小则按当前缩放等待目标视口。原生恢复失败保留紧凑布局并提示重试，不伪报恢复完成。此逻辑仅属于 PC 桌宠显示，不改变任务执行或手机端业务流程。

所有姿势都按素材 alpha 轮廓生成原生命中区域，附加按缩放计算、至少 6px 的抓取 / 小动作余量；被拎起时还计入上提位移。轮廓余量覆盖倾斜和点头的最大位移，不依赖逐帧更新，另外包含气泡和菜单的操作范围。仅单 alpha 的输入层应用 Region；WebView 显示窗口不裁剪，通过 `WS_EX_LAYERED | WS_EX_TRANSPARENT` 将指针交给下层，句柄重建时重新设置。这样空白处点击交给下方应用，角色和气泡由输入层接收；不使用整窗透明输入矩形作为已就绪状态。显示窗口不能套用轮廓 Region，否则 WebView2 的原生合成会在透明边缘显示黑块。此处的分层窗口穿透依据 [Windows 分层窗口说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows)。轮廓仅在姿势或布局变化时计算，桥接更新去重、串行并保留最新布局；不会每帧回读画布或每帧重建 Windows 区域。拖动期间保留原生鼠标捕获，避免越过轮廓空隙后收不到松手事件。同步失败显示诊断状态和菜单提示，不静默退回旧输入路径。

动画目标为正常 30 fps、睡眠 20 fps；用连续的帧截止时间保留 RAF 余量，避免每次重置 33.3ms 计时在 60 / 120 / 144Hz 屏幕上漏帧。姿势改变和调整大小时立即绘制；同一姿势的左右镜像、气泡方位改变也在下一 RAF 同步图像和点击轮廓，不等常规帧限额。长暂停后不积压补帧，页面隐藏时停止 RAF。减少动态效果偏好下不播放眨眼 / 点头，布局未变时跳过重复的 WebGL 绘制；布局或偏好改变立即重画，恢复动画时不重放之前的交互。声音仍是本地 WebAudio 短提示，默认静音。

WebGL 按角色实际绘制比例 × DPI 选择 1x / 2x 精度，高 DPI 放大时不先压成固定小图再放大。每个渲染器按需最多升级一次到 768×1152，缩小后保留缓冲区，避免拖动大小滑块跨阈值时反复分配；纹理不重载。最终始终绘入 384×576 逻辑矩形，所以画质提升不会改变角色大小、脚底位置、探头锚点或命中坐标。

右键大小滑块按 1% 步进实时预览；原生请求间隔至少 16ms，最多一个进行中，只保留最新待处理值，不积压中间尺寸。滑块使用固定屏幕坐标和起始轨道宽度计算本次手势，通过页面级指针监听持续接收 WinForms 转发的拖动；不能依赖原生 `SetBounds` 后会丢失的 DOM 指针捕获。调节期间固定菜单宽高，按当前工作区的最大缩放空间选择固定的左右 / 上下锚点，原生窗口与菜单使用同一锚点，避免到屏幕边缘后改向移动。松手、取消、失焦或控件卸载时结束手势并恢复菜单布局，键盘调节仍可用；一次手势只保存最终值。

设置保存串行并保留更新的本地草稿，失败回退并提示。自身预览不广播回原页面，避免迟到回执把滑块拉回旧值；主窗口保存的设置仍广播同步。窗口与 ResizeObserver 的通知合并到下一绘制帧，仅尺寸确实变化时重设画布，并在同一帧画回角色，不清空纹理或重建渲染器。主设置页仍采用明确点击“保存桌宠设置”的草稿语义。
