# Siming 本地 AI 与 LoRA 训练

## 数据与目录

- 推理模型：`%LOCALAPPDATA%\Siming\models`
- llama.cpp：`%LOCALAPPDATA%\Siming\runtimes\llama_cpp`
- 训练环境：`%LOCALAPPDATA%\Siming\runtimes\trainer`
- 训练集、检查点与适配器：`%LOCALAPPDATA%\Siming\training`

这些目录可以与小说数据目录分开。模型目录可在桌面控制面板的“本地 AI”页面修改。

## 硬件分档

| 档位 | 初始推荐 | 初始上下文 | 适用设备 |
| --- | --- | --- | --- |
| 标准 | Qwen3.8 27B UD-Q3_K_XL（文本） | 32K | 16GB 及以上显存配合约 32GB 内存 |
| 高质量 | Qwen3.8 27B UD-Q4_K_XL | 32K | 24GB 及以上显存 |

这些只是首次选择的建议，不是上限。模型中心的“启动参数”可设置上下文 token；保存后，手动启动和任务自动启动均使用该模型的同一份设置。未保存专属启动参数时，任务设置中的上下文仍可覆盖首次推荐值。若机器内存或显存不足，启动会保留 llama.cpp 的诊断并失败，不会静默缩短上下文后继续运行。

内置目录提供 Qwen3.6 27B Q4、Qwen3.8 27B Q3 与 Q4 GGUF。Q3 目录项只安装文本推理所需的语言模型，不承诺视觉输入。16GB 显存设备上的 Q3 实测可运行 64K 上下文，但默认 32K 留有更多显存余量；96K 虽能启动，长提示处理会明显变慢。低于 16GB 显存或不满足本机推荐条件的设备仍可自行选择模型，但不会收到未经验证的 27B 推荐。模型中心支持把已有 GGUF 登记到对应内置目录项，也支持以自有模型标识登记其他 GGUF 或下载直链。登记本机文件不会复制、移动或在移除登记时删除源文件。

在 Windows 桌面版使用已测试的 Qwen3.8 27B Q3 文件：

1. 在“模型与训练”顶部点击“使用本机 llama-server.exe”，选择现有 llama.cpp 的 `llama-server.exe`；若本机没有运行时，可点“下载运行时”。
2. 在 Qwen3.8 27B Q3 行点击“登记已有 GGUF”，选择 `Qwen3.8-27B-UD-Q3_K_XL.gguf`。司命校验 GGUF 与该目录项的 SHA256，原文件留在原位。
3. 点击“启动参数”。默认已填入本机验证过的 32K、Q4 KV 缓存、Flash Attention、MTP 2 与 2GB 内存缓存等参数。可视化修改后点击“保存并启动”；以后自动调用也使用保存的参数。
4. 顶部“停止当前模型”立即结束当前 llama.cpp 进程；如果要避免下次调用自动拉起，关闭“允许使用本地模型”。重新开启后可以再次启动。

下载进度中的红色叉号表示失败状态，不是关闭按钮；失败任务可“移除记录”，正在下载的任务可“取消下载”。取消后保留 `.part` 临时文件，重新安装时可继续使用已有字节。

这套 llama.cpp 进程与本机文件选择器只在 Windows 桌面端运行；手机端的模型调用仍通过其独立的 API/移动端路径完成，不依赖 PC 客户端保持运行。

## 任务路由

系统设置会保存每个 API、CLI 和本地运行时获取到的完整模型目录，并可分别为以下任务指定其中任一模型：

- 项目助手
- 新书与大纲规划
- 作品建档
- 章节写作
- 质量评估
- 拆书分析

模型选择只有一条权威优先级：本次任务明确选择 > 任务默认 > 全局默认。任务默认可以跨 API、CLI 和本地模型设置；没有任务默认时才跟随全局默认。本地模型还可在同一任务设置中指定启动上下文长度，超过模型容量时会明确拒绝保存。

## 结构化输出

本地模型通过 llama.cpp 的 OpenAI 兼容接口接入 `LLMGateway`。项目 Agent 首个模型步骤只获得 `set_tool_categories`，由模型按最新消息选择下一步骤当前入口内所需的小型能力类别（每步最多两类）；运行时再与权限和真实工具注册表取交集。立项助手只显示立项类别，正文写作在正式作品的项目助手中进行。评分、去 AI 味和建档固定流程直接使用任务能力。接口报错、工具协议中断或空工具流会如实停止并给出诊断，不会静默切换为另一条文本执行路径。要求 JSON 的独立任务会启用 JSON 模式，支持调用方传入 JSON Schema。

本机 llama.cpp 模型已在运行且支持模板与分词接口时，Agent 预算使用当前加载模型实际展开的工具模板增量，并额外预留边界余量；切换模型后重新测量。模型未启动、运行时不支持测量或使用 API/CLI 模型时，继续按 UTF-8 字节保守计算工具声明。系统提示、历史消息和工具结果仍独立计入预算，因此工具声明计数不是整次请求的总占用。手机端通过独立 API 调用模型，没有桌面端的本地 llama.cpp 运行时，继续使用相同的保守字节边界。

## 本机 Agent CLI

Claude Code、Codex CLI、OpenCode、Mimo Code、Cursor Agent、Kilo Code、Qwen Code、Hermes、OpenClaw 和 DeepSeek Harness（DSH）均使用由司命启动进程携带的临时 `siming_turn` MCP。司命会在启动时完成该 MCP 的授权，不再显示一次性授权按钮，也不再解析 CLI 输出中的 JSON 工具指令。MCP 与 API 使用同一工具类别目录和 `set_tool_categories` 步骤边界；临时 MCP 只绑定当前作品或立项，CLI 退出后失效，不修改 CLI 的全局 MCP 配置。

DSH 使用本机现有的登录、模型和 headless profile；司命通过 `--patch` 仅向本轮进程加入 `@deepseek-ai/dsh-mcp-client`。自定义 CLI 因启动协议未知，只能返回文本，不能用于立项或作品数据写入。

## LoRA 训练 Beta

首版训练仅支持 NVIDIA CUDA，建议：

- Qwen3.6 / Qwen3.8 27B QLoRA：24GB 及以上 NVIDIA 显存

训练流程：

1. 选择作品并生成训练集。
2. 检查样本数量、长度和训练/验证划分。
3. 确认拥有文本训练权利。
4. 选择基座、LoRA Rank、样本长度与训练轮数。
5. 训练任务支持暂停、继续、取消和检查点恢复。
6. PEFT 适配器转换为 llama.cpp GGUF LoRA 后登记到模型中心。
7. 新适配器默认停用，用户确认后再启用或设为写作默认。

## 远程清单

程序始终内置可离线使用的基础模型清单。发布方可以通过：

- `MOSHU_MODEL_MANIFEST_URL`
- `MOSHU_MODEL_MANIFEST_PUBLIC_KEY`

提供 Ed25519 签名的远程模型清单。签名验证失败时不会使用远程内容，并自动回退到上次验证成功的缓存或内置清单。
