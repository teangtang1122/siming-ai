# 司命 3.3.11

3.3.11 是数据库升级与模型上下文容量的紧急修复版本。它恢复部分旧作品库从 3.3.8 及更早版本升级后的可写状态，并避免常用官方模型因为缺少手工容量档案而停止 Agent 工作流。

## 数据库升级恢复

- 修复 SQLite 在重建对话消息表时启用外键约束，导致旧版遗留的无归属消息阻断迁移并让应用进入只读恢复的问题。
- 仅在升级路径实际经过受影响迁移时，使用独立迁移连接暂时关闭 SQLite 外键执行；迁移结束或失败后都会恢复并验证外键已开启，日常读写连接不受影响。
- 支持继续完成已经执行一半、但 Alembic 版本仍停留在旧修订的数据库升级，不会因已经存在的消息序号列再次失败。
- 新增 `300a33_legacy_message_integrity` 修订：无法归属到任何对话的旧消息会先完整写入审计隔离表，再从现行消息表移除；缺失的系统操作引用会清空。
- 对 3.3.10 迁移期间被 SQLite 级联规则清空的 AgentRun 消息引用，只在运行 ID、对话和相邻消息序号都能唯一证明时确定性恢复；存在歧义时保持为空，不猜测绑定。
- 升级前仍自动创建 SQLite 在线备份；未知数据库结构仍按原有安全策略进入只读恢复。

## 模型容量档案恢复

- OpenAI、Anthropic、DeepSeek、Gemini 与通义千问的常用官方精确模型 ID 可直接取得版本化容量档案，不再要求每位作者重复手工填写上下文窗口。
- Anthropic 模型列表接口返回的 `max_input_tokens` 与 `max_tokens` 会作为该精确模型的服务商元数据保存并用于上下文预算。
- 容量来源优先级固定为：作者保存的精确模型档案、本次请求明确容量、受管理本地运行时实际容量、服务商精确模型元数据、内置版本化官方清单；这些来源都不存在时使用带 `unverified` 标记的 256K 有界兜底。
- PC 模型设置新增“模型上下文窗口 tokens”。已验证模型会自动填写并锁定；自定义 API、代理别名和未报告真实模型 ID 的 CLI 可按部署文档填写，留空时由司命临时使用 256K 兜底，系统不会按名称前缀猜测。
- Android 手机直连同步修复：只有官方 API 主机与精确模型 ID 同时匹配时才自动使用公开容量；同名自定义代理可留空使用 256K 兜底，也可填写真实容量。任务模型不会错误继承另一个默认模型的容量档案。
- 256K 兜底保留未验证来源并绑定 UTF-8 字节保守计数器；只有这一有界组合可以发送，更大的未验证窗口仍会停止。

## 兼容升级

3.3.11 新增一项数据完整性修订。安装后首次启动会先备份再升级数据库；受 3.3.10 影响而停在旧修订的数据库可直接继续恢复。作品正文、正式章节、草稿、角色和正常对话不会因本次修订被覆盖。

## 下载

正式 Release 提供：

- `Siming-Setup.exe`：Windows 10 x64 或更高版本安装包
- `Siming-Setup.sha256`：Windows 安装包 SHA-256
- `Siming.apk`：Android 8.0 或更高版本正式签名安装包
- `Siming-apk-sha256.txt`：Android APK SHA-256

Windows 项目当前尚未配置 Authenticode 证书时，请在安装前同时核对 Release 提供的 SHA-256；Android APK 使用正式发布密钥签名。
