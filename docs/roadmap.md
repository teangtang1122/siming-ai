# 司命路线图

本文面向当前 3.3.x 代码线。具体已发布变化以对应版本的 Release Notes 为准；这里仅记录尚需推进的产品与工程方向，不重复维护历史版本清单。

## 当前基线

司命已经形成 Windows 桌面、Android 与用户自有 Gateway 三种运行形态。当前核心闭环包括：

- 从一句创意进入对话式立项，审阅结构化资料后建立正式作品。
- 导入既有小说并逐章建档，累计角色、世界观、关系、时间线和叙事治理资料。
- 通过受治理上下文生成未保存章节草稿，由作者决定保存、建档和继续时机。
- 使用 API、本地模型或本机 Agent CLI，并按任务独立选择模型。
- Android 离线编辑、Gateway 修订同步以及无 Gateway 的手机独立 Agent。
- Windows 安装包、签名 Android APK、双架构 Gateway 镜像和自动化发布门禁。

## 管理原则

1. 作者控制和数据安全优先于自动化程度。
2. 建档、写作、保存、恢复等核心闭环优先于新增外围功能。
3. PC、Android、Gateway、API、CLI 与 MCP 共用业务契约，不建立入口专属的简化路径。
4. 长任务必须可诊断、可取消、可从持久检查点恢复。
5. 当前代码、生成契约、文档和发布资产必须保持同一版本事实。

## P0：核心闭环可靠性

目标：任何受支持的模型入口都不会覆盖作者数据、重复执行写入或把失败伪装成完成。

- [ ] 持续扩充“生成草稿 → 作者保存 → 可选建档 → 允许下一章”的跨入口端到端测试。
- [ ] 覆盖显式任务模型、任务默认、全局默认以及临时手机凭据的完整优先级矩阵。
- [ ] 为建档候选累计、缺项修复、去重、应用与失败恢复补充更多异常模型输出样例。
- [ ] 对断流续传、重复请求、取消与应用重启执行故障注入，验证 Operation、AgentRun 和草稿状态一致。
- [ ] 持续演练旧数据库升级、未知结构只读恢复、WAL 在线备份及内容镜像 outbox 重放。

验收标准：核心写入具有确定性的幂等边界；失败后保留已完成结果，并向作者给出真实的恢复入口。

## P1：跨端能力收敛

目标：Android 在线、离线与独立 Agent 的差异均有明确产品语义，不以隐藏降级冒充 PC 完整能力。

- [ ] 按 `contracts/mobile-pc-parity.json` 逐项收敛仍为 `partial` 的能力，并同步测试和生成文档。
- [ ] 将手机独立 Agent 的通用对话与工具运行补入可迁移的审计记录，而不仅记录写章检查点。
- [ ] 评估 Android 离线版本历史、角色专用配置和世界观关系编辑的安全实现顺序。
- [ ] 保持 Gateway 在线写入复用 PC 领域命令；仅在断网时进入 revision outbox。
- [ ] 为同步冲突、tombstone、撤销设备和跨版本升级建立稳定的多设备回归场景。

验收标准：能力契约中的每个差异都有原因、用户提示、幂等策略和回归证据。

## P1：架构与可维护性

目标：在不改变业务语义的前提下减少超大模块和兼容层，让权威路径更容易验证。

- [ ] 拆分 `context_orchestrator.py`、统一助手流、建档编排和本机 CLI 适配器等超大模块。
- [ ] 将 `gateway` 纳入模块所有权清单与架构门禁，明确其与 `story`、`operations` 的依赖方向。
- [ ] 继续将路由中的编排下沉到 application service，并保持路由不直接访问 ORM 或提交事务。
- [ ] 删除已经没有数据迁移职责的 legacy facade、旧命名和重复测试；兼容读取与日常业务路径保持隔离。
- [ ] 逐步降低前端大页面、页面级 API 直连和 `useEffect` 基线。

验收标准：架构检查维持零错误，存量 warning 数量下降，相关模块的公开契约不发生无意漂移。

## P2：作者可见性与诊断

目标：作者能够理解 AI 读取了什么、正在做什么、为什么停止以及下一步能做什么。

- [ ] 在写作前更直观地展示 ContextManifest 摘要、来源覆盖和预算取舍。
- [ ] 为模型路由、CLI/MCP preflight、建档补全和同步冲突提供可导出的脱敏诊断包。
- [ ] 完善项目级记忆管理，包括来源、适用范围、停用和删除。
- [ ] 统一桌面与 Android 的运行阶段、错误原因、重试语义和作者确认文案。
- [ ] 继续补齐窄屏、键盘操作、读屏标签以及 loading/error/empty 状态。

## P2：发布与供应链

目标：所有正式资产可复现、可验证，并与同一 tag 精确对应。

- [ ] 统一开发、Gateway 镜像与 Windows 打包使用的 Node.js/npm 版本真源。
- [ ] 取得可信 Windows Authenticode 证书后恢复签名与时间戳强制校验。
- [ ] 保持 Windows、Android、Gateway、前后端版本和 Release Notes 同步。
- [ ] 定期升级锁定依赖并执行安装包、APK、amd64/arm64 镜像的完整冒烟验证。
- [ ] 随网络监听、凭据存储和更新策略变化同步修订桌面与 Gateway 威胁模型。

## 近期推进顺序

### 3.3.x 稳定线

只处理核心闭环缺陷、发布阻断、文档/版本漂移和低风险测试补强，不继续引入新的平行业务路径。

### 下一次次版本迭代

优先从“跨端部分对齐”“超大模块拆分”“上下文可见性”中选择不超过三个可独立验收的主题。版本范围应在 `develop` 集成验证后再确定，不预先用路线图承诺具体发布日期。
