## Windows 3.5.0 覆盖安装

用户截图显示替换安装目录内 `_internal/ucrtbase.dll` 时发生 `MoveFile failed; code 5`（拒绝访问）。没有取得反馈用户的进程列表或安装日志，因此无法仅凭截图排除权限或安全软件因素。

本地代码检查确认两个问题：

- 关闭主窗口没有同步关闭桌宠窗口；pywebview 会等待所有窗口关闭，隐藏桌宠可能留下后台进程和已加载的 DLL。
- 安装器在复制文件前清理整个旧 `_internal`，缺少清理前的可替换检查，失败时存在旧运行库被部分清理的风险。

修复把桌宠生命周期绑定到主窗口的 `closed` 事件。在 `PrepareToInstall` 中以不写入文件的方式检查主程序和旧运行库的写入、删除权限；失败时阻止整次安装，保留旧文件，提示保存工作、退出相关进程后重试。检查最多短暂重试 2.5 秒，允许应用内更新的原进程正常退出。安装日志默认开启。

验证使用生产 Inno 脚本和最小惰性测试载荷，隔离安装身份、快捷方式和注册信息。分别占用主 EXE、ucrtbase.dll、嵌套 pyd、旧运行库中待删除文件，确认安装失败时旧目录逐字节不变，释放占用后升级成功、废弃运行库文件被清理、运行库之外的作者文件保留。另验证全新安装。

## OpenCode 免费模型

本机 OpenCode CLI 为 1.18.31。执行 `opencode models opencode --refresh` 后，目录包含 `opencode/mimo-v2.6-flash-free`、`opencode/ling-3.1-flash-free`、`opencode/fledge-alpha-free` 等；旧内置名单中的 `x-preview-f-free`、`hy3-free` 未出现在本次 CLI 输出中。这不能单独证明这些 ID 在所有服务入口都已下架。

通过司命真实连接测试路径调用 Big Pickle 和 MiMo V2.6 Flash，分别耗时 32.11 秒和 33.98 秒，均返回：

> OpenCode's free tier can only be used from within OpenCode

测试使用独立工作目录和连接测试文本，保留现行只读权限和 MCP 隔离配置。没有修改真实小说、用户模型配置或伪造服务请求身份。该结果确认司命当前调用方式遭到服务端拒绝；不能据此断言官方客户端、所有用户账户或付费模型也不可用。反馈用户的原始检测报错尚未取得。

修复内容：

- 显式重新检测时向 OpenCode 传递 `--refresh`，每次激活复用已取得的目录，避免重复刷新。
- 移除过时的内置模型名单；目录取得失败时明确失败，不冒充实时结果。
- 删除执行和配置注册时对作者指定模型 ID 的静默替换，普通调用和建档均使用真实选择。
- 快速开始配置只能选当前 CLI 目录中的免费模型。
- 单独识别服务端调用限制，保留原始错误，停止继续测试剩余免费模型；界面明确提示选择其他可用配置。

这些改动修正发现、诊断和状态，不代表服务方已经允许当前免费调用方式。OpenCode 安装仅在 Windows PC 提供；手机通过 Gateway 使用同一后端的模型调用契约，没有另设本地模型名单或替换路径。

官方参考：[免费模型及其时效](https://opencode.ai/docs/zen/)、[CLI 模型目录刷新](https://opencode.ai/docs/cli/)。

### 官方限制复核

2026-10-06 进一步读取官方仓库 Issue #49580 及其评论。项目协作者 `rekram1-node` 在 2026-09-18 的[答复](https://github.com/anomalyco/opencode/issues/49580#issuecomment-5723289721)中明确说明：他们正在收紧反滥用检查，免费层不能用于其他 Agent 执行框架；该限制仅针对免费层。他还说明此前误拦官方客户端上下文压缩的问题已解决，高度定制的配置仍可能出现误判。

结合司命当前将 OpenCode CLI 作为内部模型执行器的实现与实际服务端拒绝，可以确认这条接入路线受到上述免费层限制。不能再把问题仅归结为模型名称过期，也没有证据表明需要更换一套新的调用接口。没有尝试伪造客户端身份、修改上游校验或放宽工具权限来规避限制；名单刷新与错误诊断修复并不意味着免费接入已经恢复。
