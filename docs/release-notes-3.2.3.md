# 司命 3.2.3

3.2.3 调整 Windows 安装版更新校验策略：在项目暂时没有 Windows Authenticode 代码签名证书的阶段，不再因为安装包未签名而阻止应用内更新；SHA-256 完整性校验仍然是强制条件。

## 主要改进

- Windows 安装包更新暂时取消 Authenticode 可信签名强制校验。
- 下载更新时仍必须取得发布页提供的有效 SHA-256，并在下载完成后逐字节复核。
- 安装前会再次计算本地安装包 SHA-256；如果文件被修改或损坏，仍会拒绝安装。
- 系统设置页明确显示“当前阶段暂不校验代码签名”，避免与实际行为不一致。
- 保留现有 Windows 签名验证实现与开关，后续配置正式代码签名证书后可以重新启用强制校验。

## 从 3.2.1 / 3.2.2 升级

3.2.1 和 3.2.2 已经把 Windows 代码签名校验写入客户端本体，因此它们仍会拒绝应用内安装未签名的更新包。升级到 3.2.3 这一次请从官方 Release 手动下载并运行 `Siming-Setup.exe`。

安装 3.2.3 后，后续版本即使暂时没有 Authenticode 签名，也可以在应用内通过 SHA-256 校验后完成更新。

## 发布资产

- `Siming-Setup.exe`：Windows 10 x64 或更高版本安装包。
- `Siming-Setup.sha256`：Windows 安装包 SHA-256 校验文件。
- `Siming.apk`、`Siming-apk-sha256.txt`：Android 客户端及校验文件。

> 安全说明：SHA-256 可以检测下载文件是否与发布方给出的哈希一致，但不能提供 Authenticode 所提供的发布者身份认证。待项目具备可信 Windows 代码签名证书后，应重新启用签名强制校验。
