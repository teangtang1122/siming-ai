# 司命 3.4.4

3.4.4 修复手机独立建档在模型持续输出时仍报 `timeout` 的问题。手机建档与 PC 对齐为等待有效模型输出的超时机制，并统一 DeepSeek 建档参数。本次同时发布 Android、Windows PC 安装包和 Gateway 镜像。

## 手机建档超时与进度

- 取消建档请求原有的 150 秒总时限。等待第一条或下一条有效模型输出最多 300 秒；持续收到正文、思考或有效工具参数时重新计时，因此正常长输出可以超过 5 分钟。
- 心跳、空数据帧和只有角色标记的帧不算有效输出；本机处理进度回调的时间不计入模型等待。收到 Responses 完成事件后立即结束接收，不再等待服务器关闭连接。
- 建档直接使用从 PC 导出的模型请求契约：温度 0.1、输出上限 20,000 tokens，并遵守手机配置的较小输出预留；DeepSeek 建档关闭深度思考，不改变其他任务的设置。
- 根据真实流事件显示等待响应、分析资料、返回内容和接收工具参数。超时错误说明连续多久没有有效输出，避免将所有超时都误报为手机网络故障；模型输出截断和未完成响应也有独立错误提示。
- 取消会终止阻塞中的 HTTP 请求。中断时不执行尚未完成的工具调用，保留正文与已接受候选计划；作者明确重试后复用前提未变化的计划，已完成章节不重复建档。

## PC/Gateway 与升级

本轮行为修复位于 Android；PC/Gateway 将既有建档参数提取为共享常量，执行行为未变。手机独立建档无需连接 PC，也不要求 PC/Gateway 为本次超时修复升级。若要同步手机建档结果，PC/Gateway 仍需 3.4.3 或更高版本。

本次对齐的是单次模型流的等待语义。PC 保留原有的有限重试和检查点恢复；手机中断后由作者通过持久化计划明确重试，尚未移植 PC 的流恢复协议。完整范围见 [手机建档回归说明](https://github.com/teangtang1122/siming-ai/blob/v3.4.4/docs/testing/mobile-independent-cataloging.md)。

## 测试范围

- 本地通过 353 项 Android JVM 测试、7 项 Android API 35 模拟器测试和 64 项后端定向回归；Android 构建与 Lint、提示词资产漂移、移动端能力契约及架构检查通过。
- 同一组合成流样例分别驱动 PC 的 DeepSeek 适配器/网关和 Android HTTP 客户端，验证持续输出、无效心跳、中途停顿和首个响应超时。对照测试关闭 PC 自动重试与恢复，以验证单轮完成边界。
- 模拟器覆盖前 4 章已完成、第 5 章中途超时的场景，验证没有部分写入、候选计划仍在、同一任务明确重试后完成；另覆盖取消阻塞读取和 Responses 已完成但连接未关闭。
- 正式安装包由版本标签流水线重新构建，并执行前后端、Android、Windows 安装冒烟与发布后下载校验。测试数据均为合成样例，没有使用真实用户作品作为公开测试数据。

**既有 AI 实际运行问题分析与测试主要基于 DeepSeek API 的 `deepseek-flash`。本次超时修复使用模拟模型调用和网络故障回归，尚未完成真实 DeepSeek 端到端验收。使用其他模型或 CLI 可能存在未知 bug，尚未完成同等范围的实机验证。**
