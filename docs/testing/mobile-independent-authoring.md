# 手机独立操作验收

本次改动以 3.4.4 为基线。手机 API 的执行位置固定在 Android；保存了 Gateway 地址，或者电脑暂时不可达，都不会切换本机资料操作的执行路径。

## 操作范围

| 操作 | 手机独立行为 |
| --- | --- |
| 导入与项目包 | TXT、Markdown、DOCX 和司命项目包在手机导入；完整包保留原集合和实际历史 |
| 资料编辑 | 作品、正文、大纲、角色、世界观、伏笔和治理写入本机事务，维护关联与状态 |
| 草稿 | 新章保持未保存；手机生成、导入和从 PC 带来的草稿都可本机修改、保存或丢弃 |
| 章节历史 | 查看、逐行比较、恢复；恢复产生新版本，回退受影响建档并要求重新建档 |
| 排序 | 完整章节列表及同级大纲排序在本机校验和保存 |
| 角色高级页 | 双向关系、AI 配置和历史版本独立查看或修改；拒绝跨作品 ID、自关联和重复边 |
| 世界观高级页 | 从实际本机记录读取建档版本和时间线 |
| 治理 | 本机校验解决章节、说明和复检证据，保留状态迁移审计；不得直接跳到已解决 |
| 导出 | TXT、Word（DOCX）及 PDF 均在手机生成，按正式章节阅读顺序导出 |
| 删除作品 | 移除当前手机副本、保留的原包及同步队列；其他设备副本保留，后续不自动重新下载 |
| AI 立项、写章和建档 | 配置手机 API 后在手机执行，保存 Gateway 不改变路线；取消与重试由本机任务控制 |

跨设备同步、读取只存在于另一台设备的会话，以及作者显式选择的 PC 模型仍需要对应 Gateway 在线。这些入口保留明确的远程标识；未配置 API 时可以先完成本机资料操作。

旧 PC 立项草稿提供“转为手机独立立项”：从手机已保存的结构化资料继续，保留创意、阶段和会话记录，后续编辑、确认与建立作品全部使用现有手机立项流程。移除立项草稿只移除手机副本，后续同步不会自动恢复它。

## 数据与同步约束

- `LocalAuthoringStore` 是手机普通资料写入边界，正文版本、历史、检查点、建档回退和操作回执在同一 Room 事务中保存。
- 别名及大纲角色关系使用实际 ID。替换关系先校验完整集合，再一次性替换；不以用户措辞推测目标。
- 章节版本、治理状态和高级命令按顺序确认。网络中断后使用同一命令 ID 重试；不能丢弃尚未确定结果的旧操作。
- PC/Gateway 接收命令后调用现有领域服务，将正文及其衍生记录、删除标记放进同一同步事务。手机回执只清除完全匹配的旧记录，不清除作者后来修改的版本；核对完整副本后移除旧本机历史 ID，防止历史重复。
- 单部作品刷新不推进全局拉取游标，避免跳过其他作品尚未接收的修订。
- 导入回执和初始同步版本在同一后端事务保存。首次连接时以该固定版本接续手机修改；回执丢失后重试也不会覆盖 PC 后来修改的资料。
- Room 5→6 新增本机删除排除表，并一次性把旧版手机 Key 的 Gateway 立项草稿改为设备执行；保留创意、阶段资料与会话记录。显式 PC 模型会话不迁移执行主机。
- 草稿修改、丢弃和保存状态也进入命令日志；同步时校验原草稿正文及正式章节归属，防止已经处理的草稿因刷新再次出现。

## 自动化验证

设备测试使用隔离的 Android API 35 模拟器与独立测试包，不接触真实手机资料。

本轮结果：Android JVM 347 项、设备回归 20 项、全新应用数据下的“稍后配置”验收 1 项，以及后端相关回归 101 项均通过。Debug、Android Test APK 和 lint 构建通过；架构、导入边界与 28 项能力契约检查通过。

- `LocalAuthoringInstrumentedTest`：无 Gateway、保存不可达 Gateway 两种状态；历史、恢复、排序、修订基准版本、角色配置、关系事务、治理迁移、关联删除、PC 草稿本机编辑和丢弃、旧回执保护新修改、DOCX 与实际 PDF。
- `LocalAuthoringSyncInstrumentedTest`：模拟 PC 已恢复但回执丢失，确认同 ID 重试只执行一次，后续手机修改按顺序同步，历史不会重复；验证导入回执丢失后的首次同步，以及两端真实修改冲突保留。
- `MobileCatalogingInstrumentedTest`：独立建档、超时后保留计划、明确重试、取消、建档前后修改、同步顺序，以及恢复章节时回退生成档案并保留作者之后的手工修改。
- `ProjectDeletionInstrumentedTest`：本机、已同步及上传未确认作品均可移除；无需先上传或连接 PC。
- `ProjectPackageChapterStateMigrationInstrumentedTest`：旧数据库升级后保留正文、版本、待同步队列与立项资料，修复执行主机记录。
- `DeferredSetupInstrumentedTest`：在全新测试应用数据下验证“稍后配置”和重启后进入本机作品库。
- PC 与 Android 共用 `mobile-authoring-input-v1.json`、`mobile-chapter-diff-v1.json` 和 `mobile-governance-transitions-v1.json`，校验输入长度/类型/枚举、差异算法和治理状态门槛。
- 后端覆盖新增命令、同步副作用、角色和章节规范、项目包、建档接收及提示词漂移；同时运行架构、导入边界和质量检查。

导出测试在设备生成含 150 段中文的 4 页 PDF，检查页面尺寸和首尾段落，并在主机渲染检查与提取全部段落。文本提取会归一化字体映射中的兼容字及布局空白。DOCX 检查 ZIP 中的正文 XML、特殊字符转义及首尾正文。

本轮模型与网络验证使用合成资料、模拟模型和 MockWebServer，未调用真实 DeepSeek API，也未执行真实 CLI。现有建档测试沿用 DeepSeek 接口契约；其他供应商、实际移动网络和具体手机系统仍需实机测试。

## 平台差异

- Android PDF 使用系统字体与原生分页，版式可能与 PC 不同；不依赖桌面导出服务。
- 角色和世界观历史只展示实际保存或导入的版本；本次不生成缺失历史，也不新增 PC 本身未提供的角色/世界观历史恢复入口。
- 手机不内置桌面本地模型、CLI、MCP 或训练运行时。配置手机 API 即可完成移动端写作流程。
- 独立立项使用本机事务和会话记录追踪执行；未连接 Gateway 时不会生成 PC 服务端的 Operation/AgentRun 记录，跨设备审计范围仍按能力契约说明。
- 新增高级操作与草稿状态命令需要相应版本的 PC/Gateway 接收。旧 Gateway 拒绝时会保留手机结果及错误，不影响本机独立使用。

以上记录为 3.4.5 的本地功能验收。正式安装包由对应版本标签的发布流水线重新构建、签名并校验，发布范围见 [3.4.5 发布说明](../release-notes-3.4.5.md)。
