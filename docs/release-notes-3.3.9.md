# 司命 3.3.9

3.3.9 修复已有章节无法安全交给 AI 修订，以及章节修改后重新建档容易追加重复大纲/时间线的问题。

## 主要变化

- AI 现在可以通过现有章节写作工具生成“修订候选”。候选与正式正文完全分离，作者必须先对比、应用，再明确保存到原章节。
- 网页和 Android 保存已有章节时增加版本检查。其他页面或设备先保存后，旧编辑器会收到冲突提示，本地修改不会静默覆盖新版本。
- 修订候选保存后沿用原章节 ID，版本号递增，并生成可恢复的 `AI 修订` 快照；不会新建第二章数据。
- 建档优先更新章节已经关联的大纲节点，保留作者立项时的标题与规划摘要，只更新实际发生内容。
- 对旧版本已经误建的重复章节点，重新建档时会在唯一、安全匹配的情况下恢复原规划节点，并迁移子场景后删除重复容器。
- 修改章节后重新建档会对账更新场景、角色/设定时间线和章节关联，清理本章上一版本已失效的 catalog 派生记录。
- 全局角色和世界观实体不会因为单章删改而被删除；重建较早章节也不会回退后续章节已经形成的当前状态。
- Web、Gateway 与 Android 使用同一修订身份和基准版本契约。

## 数据库升级

启动 3.3.9 时数据库升级到 `300a27_chapter_revision_drafts`。升级为持久化章节草稿增加修订目标和基准版本字段，不修改已有正式章节正文。

完整技术说明见 [3.3.9 修复文档](chapter-revision-cataloging-reconciliation-fix-3.3.9.md)。
