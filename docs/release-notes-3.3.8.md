# 司命 3.3.8

3.3.8 是合并补丁版本，集中修复大纲保存、已有章节 AI 修订和章节重新建档的一致性问题。它不会让 AI 自动覆盖正式正文，也不会在重新建档时默认复制第二份章节、大纲或时间线数据。

## 大纲与角色保存

- 新建大纲节点关联 0、1、2 或更多角色时，服务端都会在返回前完整持久化关系；响应、后续读取和数据库记录保持一致。
- 大纲关系序列化现在可以安全处理尚未写入时间戳的对象，避免多条关联排序触发异常并回滚整个节点。
- 跨作品角色或无法解析的 AI 角色名称会在变更前整体拒绝，不再静默保存不完整关系。
- 更新大纲时，未提供角色字段继续保留现有关联；显式空列表会清空关联。
- PC 大纲和角色编辑器在新建失败时会显示内联错误与即时提示，保留表单、编辑目标和重试能力。
- 迟到的旧保存请求不能覆盖作者已经切换的目标或保存后的继续编辑。

## AI、Gateway 与 Android 一致性

- 手工大纲、AI 大纲工具和大纲草稿确认共用同一个角色关联替换原语，不再维护分叉的清空与追加逻辑。
- Gateway 对多角色、显式清空、字段缺失和跨作品校验使用与 PC 相同的业务语义。
- Android 离线确认 AI 大纲草稿时，会先把角色名称解析为当前作品的真实角色 ID，再写入与 PC/Gateway 一致的关联对象；未知角色会在正式写入前明确失败。

## 已保存章节修订与保存冲突

- AI 可以通过现有章节写作工具为已有章节生成独立的“修订候选”，不再因为章节已保存而只能拒绝。
- 修订候选与正式正文完全分离；作者必须先对比、应用到编辑器，再明确保存到原章节。
- 网页和 Android 保存已有章节时携带加载时版本。其他页面或设备先保存后，旧编辑器会收到 HTTP 409 冲突提示，本地修改不会静默覆盖新版本。
- 接受修订候选时沿用原章节 ID、递增版本号，并生成可恢复的 `AI 修订` 快照；不会新建第二章数据。
- 候选目标、章级大纲归属和基准版本均由服务端校验，过期候选会保留供人工对比，但不能直接覆盖正文。

## 建档与上下文稳定性

- 新建角色时间线、世界观时间线和章节摘要后，候选记录与应用日志会保存有效的目标 ID。
- 建档上下文中的时间线排序可安全处理尚未生成时间戳的记录，并以稳定次级键保持确定性。
- 首次建档优先更新章节已经关联的立项大纲节点，保留作者标题和规划摘要，只更新实际发生内容。
- 对旧版本误建的重复章节点，重新建档时会在唯一、安全匹配的情况下恢复原规划节点，迁移子场景并删除重复容器。
- 修改章节后重新建档会对账更新场景、角色/设定时间线和章节关联，并清理本章上一版本已失效的 catalog 派生记录。
- 全局角色和世界观实体不会因为单章删改而被删除；重建较早章节也不会回退后续章节已经形成的当前状态。
- 候选和应用日志继续作为追加式审计历史保存；只有用户可见的当前投影会被调和。

## 数据库升级

启动 3.3.8 时数据库升级到 `300a27_chapter_revision_drafts`。升级为持久化章节草稿增加修订目标和基准版本字段，不修改已有正式章节正文。既有作品无需手工迁移。

完整技术说明见 [3.3.8 已保存章节修订与重新建档对账修复文档](chapter-revision-cataloging-reconciliation-fix-3.3.8.md)。

## 下载

正式 Release 提供：

- `Siming-Setup.exe`：Windows 10 x64 或更高版本安装包
- `Siming-Setup.sha256`：Windows 安装包 SHA-256
- `Siming.apk`：Android 8.0 或更高版本正式签名安装包
- `Siming-apk-sha256.txt`：Android APK SHA-256

Windows 项目当前尚未配置 Authenticode 证书时，请在安装前同时核对 Release 提供的 SHA-256；Android APK 使用正式发布密钥签名。
