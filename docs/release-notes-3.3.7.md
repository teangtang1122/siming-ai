# 司命 3.3.7

3.3.7 统一正文写作与新章规划的上下文选材流程。模型先检索候选资料、复核并明确选择，服务端再读取精确原文；项目角色和大纲数量不再自动扩大生成上下文。

## 统一模型选材

- 正文写作和新章规划共用 `prepare_task_context → search_task_context → submit_context_evidence` 状态机。
- 默认基线只包含任务硬锚点、精简立项约束、文风、作者本轮要求和显式固定资料。
- 角色、关系、章节、世界观、时间线、记忆和叙事治理资料均由模型按需检索并选择。
- 候选搜索只返回短摘要与真实 ID；最终生成前由服务端校验作品归属、来源哈希、目标和一次性选择令牌。
- 32k token 是精简软目标，超过时只提醒；唯一输入硬边界由当前模型上下文窗口、输出预留和安全余量动态计算。

## 未保存大纲提案

- `outline_writer` 不再直接创建正式大纲，而是生成持久化 `OutlineDraft`。
- 聊天区显示紧凑的大纲提案卡；大纲页和 Android 可查看、编辑、恢复、重新生成或放弃提案。
- 作者确认时才事务性写入 chapter 与 section，并校验生成后正式大纲是否发生变化。
- “确认大纲并写正文”先保存并取得真实章级节点 ID，再以作者点击启动新的正文任务。
- 用户要求写下一章但不存在可用章级大纲时，本轮只生成提案并结束，不会静默补纲后继续写正文。

## 单一业务路径与跨端一致性

- 删除正文专用的旧上下文预览和规划自动拼装路径；两个生成器都只消费统一选材结果。
- PC、内部 API、直接 MCP、本机 CLI 与 Android 使用相同任务类型、预算、令牌和草稿状态语义。
- 新增大纲草稿数据库迁移、并发确认、令牌失效、跨作品隔离和终止回合测试。
- 已与 3.3.6 的前端最后请求生效机制集成，迟到的历史请求不会覆盖正文草稿或大纲提案状态。

## 下载

正式 Release 提供：

- `Siming-Setup.exe`：Windows 10 x64 或更高版本安装包
- `Siming-Setup.sha256`：Windows 安装包 SHA-256
- `Siming.apk`：Android 8.0 或更高版本正式签名安装包
- `Siming-apk-sha256.txt`：Android APK SHA-256

Windows 项目当前尚未配置 Authenticode 证书，安装前请同时核对 Release 提供的 SHA-256；Android APK 使用正式发布密钥签名。
