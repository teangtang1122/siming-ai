# Siming Android

Android 客户端位于 `mobile/android`，最低 Android 8.0（API 26），目标 API 35。它保存可写离线副本，可直接连接用户选择的 OpenAI 兼容 API，也可连接用户自有 Gateway 做跨设备同步；不包含本地模型、OpenCode、CLI、MCP 或训练运行时。

## 手机交互

- 书架直接展示与搜索作品；“新建”集中提供 AI 立项、空白作品、小说导入和项目包导入。配置模型后返回会保留尚未提交的立项输入。
- 书内底栏为“写作 / 大纲 / 助手 / 资料”。写作首屏提供 AI 写作和手动新建；角色、世界观、伏笔、叙事治理、建档与导出从资料目录进入。
- 立项对话独占页面；资料按钮打开完整阶段目录，审阅页底部固定生成或确认操作。编辑默认展示中文字段表单，原始结构编辑保留在高级入口。历史对话和模型选择按需展开。
- 保留系统字号，不强制缩小字体；键盘弹出时收起主导航、缩放可用区域，输入与保存操作保持可达。AI 草稿、已保存正文、阶段确认和建档仍遵循下述共同契约。PC 的侧栏与手机的底栏仅为呈现差异。

## AI 与 PC 一致性契约

PC 快速开始仅引导获取 API Key 和配置 API；手机的独立 API 配置使用相同的“通过真实对话验证后才可用”原则，不依赖电脑运行。平台入口不同：手机还可主动连接自有 Gateway；PC 的本地模型和已有 CLI 从模型中心及模型设置进入，不放在快速开始中。手机使用通用 OpenAI 兼容配置表单，PC 则提供具名服务商表单；均不提供 OpenCode 免费模型自动接入。

- 首次启动可选择“稍后配置”直接进入本机作品库，导入、查看和手动编辑资料无需 API 或 Gateway。这个选择会持久保存；需要 AI 或跨设备同步时，再从设置配置直连 API 或连接自己的 Gateway。
- 作品、章节、大纲、角色和世界观统一在手机的 Room 事务中增删改，并记录可选同步队列。连接状态不决定业务路径。历史、差异比较、章节恢复、排序、角色关系/AI 配置及世界观版本和时间线均从本机资料完成。
- 项目助手默认使用手机 API；同时配置 Gateway 时可显式选择 PC 模型。手机 API 的提示词、工具执行和存储在手机完成，Key 不因保存了 Gateway 地址而发送给 PC。远程模型会话与跨设备同步需要其主机运行。
- `scripts/export-mobile-prompt-contract.py` 从 PC `PromptSpec`、写作规则和工具注册表生成 `pc_workspace_prompt_contract.json`；手机运行同源函数调用循环和章节/角色/大纲/世界观二级生成器，本地工具写入手机数据库与 outbox。
- “AI 立项”复用 PC `creation.novel.stage@3.0.0` 的预设、动态采访、8 阶段 PromptSpec、影响依赖、JSON 修复与数据契约。手机 API 始终在 Android 执行，不会因 Gateway 已配置而改为 PC 代办；作者显式选择 PC 模型时才使用远程会话。
- 旧 PC 立项草稿可以从手机已保存的资料“转为手机独立立项”，继续编辑、确认并建立作品。立项草稿可直接从手机移除，后续远程刷新不会自动恢复它。
- 核心立项资料通过最终审阅后即可“建立正式作品档案”，前三章细纲与 PC 一样可以建档前确认，也可以稍后完善。Gateway 路线调用 PC `/apply`；纯手机路线按相同实体字段建立作品、角色关系、世界设定关系、卷纲以及已确认的章节/场景细纲，并进入离线同步队列。
- 外部小说导入与 PC 共用 TXT / Markdown / DOCX 格式边界和 20 MiB 上限。在本机安全解码文本或提取 DOCX 正文，再按与 PC 一致的章节标题识别规则原子保存，不会用错误编码替换字符强行导入。
- 司命项目包使用独立 `.siming-project` 入口和磁盘流式处理，不经过小说 `ByteArray` 解析器。离线导入保留完整原包与幂等请求键；联网时先上传项目包，再回放该作品的普通 outbox。
- 删除作品始终移除当前手机副本、原包和待同步记录，其他设备的副本保留；本机排除记录防止作品被自动重新下载。已经同步或上传中断的作品也能本地删除。删除、项目包导入与同步串行执行。
- TXT、Word（DOCX）和 PDF 均由手机导出，包含按阅读顺序排列的正式章节。PDF 使用 Android 字体和分页，与 PC 的具体版式可能不同。
- 保存正文、恢复版本和治理状态变更在本机维护历史、检查点和建档失效状态。章级恢复会回退受影响的建档来源，并要求重新建档；作者后续手动改动不会被旧生成值覆盖。已导入包只提供其实际保留的历史，不补造缺失历史。
- 高级操作使用稳定命令 ID 与版本/实体守卫按顺序同步到 PC 相同领域服务。网络中断后重试同一 ID；同步失败保留手机结果，PC/Gateway 需升级后才能接收新增命令。
- 项目包首次同步以导入回执记录的初始版本为基准，既允许回放手机离线修改，也保留 PC 在导入后产生的真实版本冲突。
- 项目包在手机独立模式下直接恢复大纲、世界观、伏笔及叙事治理副本，使用与 PC 相同的记录类型；卷章层级、角色关联和治理引用按统一 UUIDv5 规则重建。版本、检查点与当前资料分别识别，导出时按具体记录类型归入原集合。`project-package-v1-authoring.json` 是两端导入回归测试共用的虚构数据，不包含用户作品。
- 完整项目包按同章、当前版本正文快照和后续建档摘要恢复续写门槛，与 PC 共用 `project-package-v1-chapter-state.json` 验证契约。升级会一次性修复已导入作品缺失的状态，并保留正文修改及已知的待建档状态；不会要求已具备证据的手机副本先连接 PC。
- `backend/tests/test_mobile_prompt_contract.py` 会重建并比较该资产。PC 提示词或工具 schema 改动后若没有重新导出，测试会失败，防止手机悄悄退化成简化提示词。

## 开发构建

Debug 安装包显示为“司命（测试版）”，使用独立应用标识与数据目录，可以覆盖旧测试版；从正式版迁入测试时需要重新导入项目，API 配置也独立保存。

```powershell
$env:JAVA_HOME = "C:\path\to\jdk-17"
$env:ANDROID_SDK_ROOT = "C:\path\to\android-sdk"
cd mobile\android
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

Debug APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。

## 正式签名

正式 APK 必须始终使用同一发布密钥。密钥文件、口令、生成的 APK、截图、模拟器数据和 `local.properties` 均被 `.gitignore` 排除；不要通过 Issue、日志或 Release 上传密钥。

```powershell
$env:SIMING_ANDROID_KEYSTORE_FILE = "C:\secure\siming-release.jks"
$env:SIMING_ANDROID_KEYSTORE_PASSWORD = "..."
$env:SIMING_ANDROID_KEY_ALIAS = "siming"
$env:SIMING_ANDROID_KEY_PASSWORD = "..."
.\scripts\build-android-release.ps1
```

脚本执行 R8 release 构建、zipalign、APK Signature Scheme 签名、签名/包名/版本验证，并输出 `release/Siming.apk` 与 `release/Siming-apk-sha256.txt`。GitHub Release 的 APK 版本必须与 `backend/app/version.py` 和 `frontend/package.json` 一致。

## 发布前检查

- 单元测试、lint、Debug 与 Release 构建通过。
- 运行 `python scripts/export-mobile-prompt-contract.py`，并确认提示词漂移测试通过。
- 在实际模拟器或手机检查直连 API 配置与模型自动获取、连接、扫码、作品库、新建/导入、编辑、离线、同步、冲突、AI 禁用/运行和关于页面。
- 分别验证手机 API（无 Gateway、有不可达 Gateway）及显式 PC 模型路线；相同输入应遵循同一工具参数结构和实体字段。独立运行验收见 [测试说明](../docs/testing/mobile-independent-authoring.md)。
- 检查紧凑手机视口与当前参考视口，覆盖加载、空、错误、禁用和完成状态并保存截图。
- 用全新安装和上一正式版升级各验证一次；确认 Room schema、令牌迁移和 WorkManager 不丢任务。
- 通过 Gateway 创建作品、编辑同一实体制造冲突、解决后再次同步；断开设备后旧令牌必须失效。


### 立项对话与历史整理

- 同一立项支持新建和切换对话；各自的原文、运行状态、检查点独立，阶段资料仍共享。新对话不复制旧聊天，Agent 通过当前立项工具读取权威资料。任务运行期间禁止新建或切换；迟到的旧对话结果不能覆盖当前对话。
- 已有单对话先按原 ID 导入规范化历史，再登记对话目录；操作幂等。日常回合不再从立项展示记录重复导入。手机独立模式的原文及检查点在本机持久化，无需 PC。Gateway 模式复用 PC 的同一系统对话存储，新增会话目录与读取接口仍校验立项归属。
- 直连设置分别配置上下文窗口、业务输出预留、历史整理初始输出额度、默认模型最大输出容量。整理使用所选任务模型的已知容量与作者配置中较小的值；自定义模型缺少容量证据时保守使用业务输出值，任务模型切换不会沿用另一模型的手动容量。
- 输出额度包含提供商计入的推理 token，不能从 1M 上下文窗口推导。Chat Completions 的官方 OpenAI 端点使用 `max_completion_tokens`，Responses 使用 `max_output_tokens`；其他兼容端点遵循各自契约。手机与 PC 的请求策略由同一目录定义。
- 截断先在容量内增长输出，再缩小待整理的完整回合前缀；不裁剪消息或拆分工具事务。每次整理恢复链最多调用模型 6 次，结构/引用修正最多一次（每个批次），与长度恢复共用额度。HTTP 传输层仍遵循各提供商已有的有界重试；总上限不代表无限重试。
- PC/API 初始整理预算通过 `CHECKPOINT_OUTPUT_TOKENS` 配置，受当前模型绑定的最大输出容量限制。无效、截断或超容量结果不能发布；失败保留完整历史和有效检查点，并在业务模型/工具执行前终止。错误码 `conversation_checkpoint_output_limit` 明确标识“历史整理输出超限”。
- 显式把 Gateway 立项转为本机时，按对话分别导入已有展示历史；PC 检查点留在原服务器，本机不会把服务器检查点伪装为本机有效检查点，后续按本机规范化来源重新整理。


### 多组手机 API

“手机 API 管理”支持新增、编辑、测试、删除和设置默认 API；每组分别保存地址、Key、协议、模型列表和容量。任务可显式选择 API＋模型，未单独绑定的任务使用默认 API 的默认模型。项目助手内部的写作、规划生成器也使用同一解析器及本轮捕获的配置目录，切换默认配置不会更改正在执行的回合。

原有单 API 加密载荷在初始化时原子迁移为配置目录，保留所有参数和任务模型；旧键随成功迁移删除，失败不覆盖原数据。日常运行只读取新目录。新增配置不会借用默认 API 的 Key，编辑地址时必须填写对应 Key；配置验证失败不会保存。

手机沿用 PC 的显式“提供商＋模型”选择语义，凭据在本机 Android Keystore 下加密，配置摘要不含密钥，不经 Gateway 同步。平台管理差异：PC 删除提供商时会清理其任务设置；手机为了避免意外改用另一服务，要求先解除任务引用并显式切换默认 API，再允许删除。删除最后一组配置后回到未配置状态。


### 建档场景候选修复

手机与 PC 的内部建档工具仅在存在当前待审场景候选时开放 `scene_outline_replace`，并把真实候选 ID 集合写入本步骤参数约束及修正回执。正式大纲 ID 不能代替候选 ID；替换须覆盖完整场景集合，校验失败保留正文、正式档案和已有候选，仍遵循原有有界重试。

叙事状态中的事件、伏笔、未结行动、故事线及读者已知事实必须为非空字符串，或包含非空 `title` 的对象；模型须按契约修正，应用不从 `content`、`event` 等字段猜测补写。两端在候选提交边界校验，错误不覆盖原摘要。唯一摘要不能单独撤回，须直接更新或与有效替代摘要同批提交。手机持久化已撤回候选并排除其正式应用，重启及重复撤回保持幂等；候选列表按 `status` 筛选。连续工具校验失败时显示具体字段或候选原因，完整回执保留在审计记录中。


### 建档工具参数格式修正

PC 与手机独立建档对正常结束但 `arguments` 不是有效 JSON 对象的响应保留原始参数及全部原生调用 ID，整批工具均不执行。只有调用 ID 完整、唯一且函数名存在时，才向同一模型返回完整错误回执；每章累计最多三次格式失败（至多两次修正），与已有步骤上限共同约束。身份缺失或重复仍明确失败，不补造 ID，不用应用层 JSON 修复器改变模型参数。截断响应继续走既有长度恢复，不与正常结束的格式错误混淆。失败和耗尽保留现有候选及完整审计；格式修正成功后仍须通过候选、归属和最终提交校验。Responses 历史只允许完整、明确标记为整批未执行的格式错误事务原样重放，不放宽普通调用的参数校验。


### OpenAI GPT-6 请求参数

统一请求策略按官方 HTTPS 端点、精确模型 ID、协议及推理档位匹配 GPT-6 契约；手机由 PC 权威定义生成策略目录。启用推理时从最终请求移除不支持的温度、采样和概率参数，显式 `none` 保留受支持的采样参数；不自动降低推理档位。Luna/Sol 的 Chat Completions 工具调用仅接受 `none`，Astra、6.1 Sol 和 6.1 Terra 的工具调用须使用 Responses；不兼容组合在发送前明确失败。自定义端点与未确认模型不按名称套用官方能力。手机预算预检和网络发送使用同一最终序列化请求。

连接探测使用同一参数策略，输出额度包含推理消耗；仅输出截断可在配置及已知容量内恢复一次，耗尽明确报告“连接测试输出超限”。HTTP 参数错误和模型不存在不会触发协议切换；自动协议探测仅针对接口路由不匹配。PC 探测可通过 `max_output_tokens` 指定上限，已保存配置的探测继承其额度；未知容量保守限制。
